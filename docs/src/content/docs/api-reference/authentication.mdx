## Overview

Whatomate supports two authentication methods:

1. **JWT Tokens** - For user sessions and frontend applications
2. **API Keys** - For server-to-server integrations and automation

After logging in, you receive an access token and refresh token. Include the access token in the `Authorization` header for all protected API requests. Alternatively, use an [API key](/whatomate/api-reference/api-keys) in the `X-API-Key` header.

## Register

Create a new user account within an existing organization. Registration requires an `organization_id`, which is typically provided via an invitation link.

<Aside type="note">
  If the email already exists and the password matches, the user is added to the organization as a member instead of creating a new account.
</Aside>

```bash
POST /api/auth/register
```

### Request Body

```json
{
  "email": "user@example.com",
  "password": "securepassword123",
  "full_name": "John Doe",
  "organization_id": "uuid"
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `email` | string | Yes | User's email address |
| `password` | string | Yes | Minimum 8 characters |
| `full_name` | string | Yes | Display name |
| `organization_id` | string | Yes | UUID of the organization to join |

### Response

```json
{
  "status": "success",
  "data": {
    "user": {
      "id": "uuid",
      "email": "user@example.com",
      "full_name": "John Doe",
      "organization_id": "uuid",
      "role": {
        "id": "uuid",
        "name": "agent"
      }
    },
    "access_token": "eyJhbGciOiJIUzI1NiIs...",
    "refresh_token": "eyJhbGciOiJIUzI1NiIs...",
    "expires_in": 3600
  }
}
```

## Refresh Token

Get a new access token using your refresh token.

```bash
POST /api/auth/refresh
```

```json
}
```

### Response

```json

  "status": "success",

  }
}
```

## Switch Organization

Switch the current browser session's active organization. On success, the server sets HttpOnly access and refresh cookies scoped to the target organization and returns the user's org-specific role and permissions. It retires the presented refresh unit and its retained immediate links; independent login sessions are unchanged.

<Aside type="note">
  Non-super-admin users must retain access to both the current and target organizations. Super admins do not require explicit membership, but platform compliance organizations remain unavailable for ordinary sessions.
</Aside>

```bash
POST /api/auth/refresh/switch-org
```

The request must carry the session's access and refresh cookies and a matching `X-CSRF-Token` header. A valid access bearer may replace the access cookie, but it does not remove the refresh-cookie or CSRF requirements. API keys cannot authorize this transition. The old `/api/auth/switch-org` route returns `409` with `error_type: "switch_client_update_required"`; reload an older client before switching.

Confirmed failures before transition use `error_type: "switch_not_applied"` and preserve the current credentials. An unknown Redis outcome uses `503` with `error_type: "switch_outcome_unknown"`; unavailable retained refresh authority uses `409` with `error_type: "switch_session_recovery_required"`. These responses set no session cookies. The current client uses scoped session recovery/sign-in instead of automatically replaying an uncertain switch. An unknown outcome does not prove that the old refresh credential survived.

### Request Body

```json
{
  "organization_id": "uuid"
}
```

### Response

```json
{
  "status": "success",
  "data": {
    "user": {
      "id": "uuid",
      "email": "user@example.com",
      "full_name": "John Doe",
      "organization_id": "uuid",
      "role": {
        "id": "uuid",
        "name": "agent",
        "permissions": [
          { "resource": "contacts", "action": "read" },
          { "resource": "messages", "action": "read" }
        ]
      }
    },
    "expires_in": 3600
  }
}
```

## Using Tokens

Include the access token in the `Authorization` header for all protected API requests:

```bash
curl -X GET "http://your-server:8080/api/contacts" \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIs..."
```

## Token Expiration

| Token Type | Default Expiration |
|------------|-------------------|
| Access Token | 1 hour |
| Refresh Token | 7 days |

<Aside type="caution">
  Store tokens securely. Never expose tokens in client-side code or version control.
</Aside>
